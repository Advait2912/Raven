# Skill: Evidence Models, Data Governance & Persistence

## Current State

- **In-memory only:** `EvidenceStore` (`raven/core/store.py`) holds lists of `Evidence`, `Observation`, and `Finding` objects
- **Sequential IDs:** `E01`, `E02`, ... generated by `EvidenceStore.next_id()`
- **No persistence:** All data is lost on server restart
- **No redaction:** Raw credential values (e.g., `alicepassword123`) appear in evidence
- **No integrity chain:** No hash chain or HMAC on evidence records

### HMAC Evidence Chain

Replace plain sequential IDs with HMAC-SHA256 chaining:

```
chain_hash = HMAC-SHA256(session_key, previous_chain_hash + SHA256(evidence_json))
```

- Session key held in application memory during assessment lifecycle
- Only `SHA-256(session_key)` stored in `hmac_session_keys` table
- Chain provides **tamper-evident** (not tamper-proof) ordering verification
- A broken chain indicates evidence was modified or deleted

### Finding States (5-state model)

```
NOT_TESTED     → Module has not run
NOT_DETECTED   → Module ran, all checks clean
UNCONFIRMED    → Suspicious observations, insufficient proof
CONFIRMED      → Deterministic validator fully satisfied
INVALIDATED    → Previously confirmed, now disproved by new evidence
```

**Rule:** Only `FindingValidator` can transition states. AI NEVER triggers state transitions.

## RedactionPipeline — Critical Requirement

### Position in Data Flow

```
Target HTTP Response
        ↓
RedactionPipeline.redact(raw_data)     ← BEFORE any write
        ↓
EvidenceStore.add_evidence(redacted)   ← Only redacted data enters storage
        ↓
SQLite evidence table                  ← Never contains raw secrets
        ↓
RedactionPipeline.redact(context)      ← Defense-in-depth before AI prompt
        ↓
AI prompt construction
```

### Minimum Redaction Patterns

```python
REDACTION_PATTERNS = [
    (r'(?i)(password|passwd|pwd)\s*[:=]\s*\S+',         'CREDENTIAL'),
    (r'(?i)(api[_-]?key|apikey)\s*[:=]\s*\S+',          'KEY'),
    (r'(?i)(secret[_-]?key|secret)\s*[:=]\s*\S+',       'KEY'),
    (r'(?i)(token|bearer)\s*[:=]\s*[\w\-\.]+',           'TOKEN'),
    (r'AKIA[0-9A-Z]{16}',                                'AWS_ACCESS_KEY'),
    (r'(?i)db[_-]?(url|password|pass)\s*[:=]\s*\S+',    'DATABASE_CREDENTIAL'),
    (r'-----BEGIN (RSA |EC |OPENSSH )?PRIVATE KEY-----', 'PRIVATE_KEY'),
    (r'(?i)(smtp|mail)[_-]?(password|pass)\s*[:=]\s*\S+','CREDENTIAL'),
]
```

### Fail-Closed Behavior

If `RedactionPipeline` raises ANY exception:
1. The evidence write is **aborted**
2. Raw data is **discarded** (never stored)
3. The assessment step is marked **FAILED**
4. An audit entry is created

This behavior is **never configurable**. No env var, config flag, or feature toggle can bypass it.

## Non-Negotiable Data Rules

1. **Redaction before storage, always.** No raw credentials in SQLite, ever.
2. **HMAC chain from first evidence write.** Not added later; built from day one.
3. **Evidence IDs are stable and sequential** within an assessment session.
4. **Container restart must not lose data.** SQLite in a Docker named volume (`/app/data`).
5. **Finding state transitions are deterministic.** Only `FindingValidator` code paths change states.
